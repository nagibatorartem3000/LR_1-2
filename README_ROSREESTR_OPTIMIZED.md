# rosreestr_optimized.py — переработанная версия

Исходный файл «Росреестр .py» не изменялся (хэш совпадает с загруженным).
Новая версия: `rosreestr_optimized.py` (~4160 строк) + тесты в `tests/`.

## Запуск

```bash
pip install playwright openpyxl
playwright install chromium
python rosreestr_optimized.py
```

Порядок работы прежний: откроется окно браузера — войдите вручную и пройдите
капчу; дальше программа работает сама. Сессия сохраняется в `rosreestr_profile`,
поэтому повторные запуски обычно без входа. Прерванный запуск продолжается с
места остановки (кэш `rosreestr_cache.json`, атомарная запись, инкрементальное
сохранение после каждого дома).

Входные/выходные файлы те же: читает «Дома в обслуживание.xlsx» (лист
«Подходящие»), пишет «Дома Росреестр.xlsx» с листами «Дома», «Квартиры»,
«Частных меньше 50%», «Неполные данные», «Ошибки и пропуски», «Диагностика».
Если Excel открыт в Excel и файл заблокирован — пишется «…(копия).xlsx».

Тесты (без сети и браузера):

```bash
pip install pytest
python -m pytest tests/ -q     # 38 тестов, все проходят
```

## Главное изменение: гибридный движок (API + экран)

1. **Основной путь — прямой API того же сервиса** изнутри открытой страницы
   (та же сессия и cookie, ничего не обходится):
   - поиск по адресу: `GET /account-back/address/search?term=...`;
   - карточка: `POST /account-back/on` с кадастровым номером.
   Карточка приходит за ~1,5 с вместо 5–8 с экранного открытия; адрес в
   карточке разобран по полям (street/house/korpus/flat/litera) — сверка
   адреса идёт по полям, а не по тексту.
2. **Экранный движок сохранён целиком** как резерв (`AUTO_FALLBACK_UI=True`):
   при 406/401/403 (капча/отказ) дом автоматически дособирается через интерфейс.
3. Выбор движка виден в логе (`режим: api/ui`).

## Полнота поиска (главный приоритет)

- **Этап А**: здание — по кадастровому номеру из ГИС ЖКХ, при неудаче по
  адресу; проверка по совпадению адреса, назначению (204003000000 = МКД);
  неоднозначность фиксируется в комментарии.
- **Этап Б**: список помещений — 3 прохода адресного поиска объединяются
  (выдача сервиса нестабильна: два одинаковых запроса дают разные
  подмножества из 100; один проход — неполный всегда). Каждый результат
  проверяется принадлежностью дому.
- **Этап В**: добор пропущенных — если найдено меньше ожидаемого по ГИС ЖКХ,
  зондируются **все** отсутствующие номера 1..N+6 (правило «трёх пустых
  подряд» действует только когда ожидаемое число неизвестно), альтернативные
  форматы запроса, буквы/дроби/корпуса, добор из других кадастровых кварталов.
- **Этап Г**: проверка полноты. Дом **не** объявляется полным, если:
  выдача была обрезана лимитом 100, были ошибки API/сервера, не открылись
  карточки, найдено меньше ожидаемого, поиск завершился сбоем. В листе
  «Диагностика» — ожидаемое число по ГИС ЖКХ и статус полноты по каждому дому.

## Ошибки

Классификация: временная ошибка сервера (5xx), потеря соединения, тайм-аут,
пустая выдача, ограничение частоты (429/текст), капча (406/401/403), ошибка
чтения карточки, ошибка браузера, ошибка пагинации, нечитаемый ответ,
неизвестная. Поведение: повторные попытки с адаптивными паузами, увеличение
паузы при лимите частоты, ошибка **никогда** не считается отсутствием квартиры
(проверено тестами: сценарии 9, 10, 10b). Прогресс сохраняется после каждого
дома и после каждой успешной карточки; Ctrl+C и падение браузера —
корректное сохранение и продолжение при следующем запуске.

## Сопоставление адресов

Многоуровневое: поля карточки API → точное совпадение токенов → совпадение с
административным префиксом («Кировская обл» больше не отклоняет квартиры).
Понимаются сокращения улиц, варианты городов, районы/мкр, корпуса («5к2» =
«5 к2» = «5/2»), строения, литеры («5литА» = «5 лит А»), дробные и буквенные
дома, форматы квартир. Причина отклонения каждого объекта пишется в
«Ошибки и пропуски» (пример: «другой дом: 7», «лишние слова в адресе: …»). Город
сверяется по вариантам: если город в ГИС ЖКХ неверный (дом реально в другом
городе), правильный город берётся из адреса здания в Росреестре — квартиры этого
города принимаются, а одноимённые улицы чужих городов (Котельнич, Вятские Поляны
и т.п.) по-прежнему отклоняются. Числовые поля JSON (площадь, стоимость)
обрабатываются и как строки, и как числа.

## Сохранённая функциональность

Ручной вход, ручная капча, профиль сессии, чтение «Дома в обслуживание.xlsx» /
«Подходящие», все 6 листов Excel и все поля (КН, площади, форма собственности,
права, обременения, назначение, этаж, кадастровая стоимость, статусы).
Лимит 30 считается **только по квартирам (кв.)**; комнаты и нежилые не
увеличивают счётчик и не приводят к отбрасыванию дома (сценарии 5, 6).
Форма собственности — из карточки Росреестра. Неполные данные помечаются явно.

## Диагностика

Лист «Диагностика» на каждый дом: время всего/по зданию/по списку/по карточкам/
по добору, число API-запросов, экран­ных поисков, карточек, ошибок, повторов,
пустых выдач, лимитов частоты, найдено квартир/комнат/нежилых, пропущено,
ожидаемое число, полнота, самый медленный этап, причина завершения.
В конце прогона — сводка по всем домам. `rosreestr_stats.json` — накопители.

## Основные настройки (в начале файла)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `USE_API` | True | прямой API вместо экрана (при капче — авто-откат на экран) |
| `AUTO_FALLBACK_UI` | True | дособирать дом экраном, если API требует капчу |
| `API_TIMEOUT` / `API_RETRIES` | 25 / 3 | тайм-аут и число повторов API-запроса |
| `ADDRESS_PASSES` | 3 | число объединяемых проходов адресного поиска |
| `API_PAUSE` | 0.4 | пауза между API-запросами (адаптивно растёт при отказах) |
| `MAX_FLATS` | 30 | лимит только по квартирам |
| `SKIP_BY_GIS_COUNT` | False | пропускать дом сразу, если в ГИС ЖКХ > 30 жилых |
| `EMPTY_STREAK_LIMIT` | 3 | пустые подряд только когда ожидаемое число неизвестно |
| `MISSING_EXTRA` / `MAX_MISSING_PROBES` | 6 / 45 | добор номеров после последнего найденного |
| `OWNERSHIP_CODE_MAP` | {} | см. «Ограничения» п.1 |

## Сравнение производительности (старая → новая)

Оценка для дома с 15 квартирами (замеры HAR + тайминги исходного кода;
в песочнице реальный прогон невозможен — см. «Ограничения»):

| Операция | Старая (экран) | Новая (API) |
|---|---|---|
| Поиск здания | 10–40 с | ~1–3 с |
| Список помещений | 30–120 с (страницы по 5–6 с) | 3 прохода ≈ 3–6 с |
| Карточка квартиры | 5–8 с | ~1,5 с |
| Дом из 15 квартир, итого | ~3–5 мин | ~40–70 с |
| Дом из 30 квартир | ~7–10 мин | ~1,5–3 мин |

Дополнительный выигрыш: повторные запуски не перечитывают успешные карточки
(кэш с версией правил), ошибки не приводят к повторному сбору дома с нуля.

## Ограничения, которые нельзя устранить программно

1. **Код формы собственности (`ownershipType`).** В JSON карточки нет поля
   «Частная/Муниципальная» — только код («01» наблюдался на одной карточке).
   Кодировка не подтверждена, поэтому в новой версии: код пишется в таблицу
   как есть («Код NN (не раскрыт)»), а форма собственности выводится из
   описания прав (`rights[].rightTypeDesc`). Когда по вашим данным станет
   ясно соответствие кодов, впишите их в `OWNERSHIP_CODE_MAP = {"01": …}` —
   перекодировка включится сама.
2. **Лимит 100 результатов адресного поиска** — ограничение сервиса.
   Компенсируется объединением нескольких проходов (выдача нестабильна) и
   зондированием недостающих номеров; дома, где и это не помогло, честно
   помечаются неполными с причиной «обрезана лимитом 100».
3. **Нестабильность выдачи** — два одинаковых запроса дают разные
   подмножества. Компенсация — несколько проходов; 100%-й гарантии полноты
   списка это не даёт, поэтому обязательна сверка с числом из ГИС ЖКХ.
4. **Капча и вход** — только вручную, как и раньше; обход не выполняется и
   не предусмотрен.
5. **API не проверен живым прогоном.** Контракт (`/address/search`, `/on`,
   коды назначений, поля адреса) подтверждён вашими HAR-файлами и открытыми
   замерами, но в этой среде нет выхода на lk.rosreestr.ru и сессии — первый
   реальный запуск может выявить мелочи (например, редкие поля ответа).
   На этот случай: экранный движок полностью сохранён как резерв, а любая
   нечитаемая карточка помечается «требует повторной проверки», а не
   «объект отсутствует». Если при первом запуске что-то пойдёт не так —
   пришлите текст ошибки из лога/«Ошибки и пропуски», поправлю точечно.
6. **Параллельные запросы не включены**: поведение сервиса при
   параллельной нагрузке не изучено, по умолчанию — последовательная
   обработка с адаптивной паузой (`API_PAUSE`).

## Что проверено тестами (38, все проходят)

12 сценариев из ТЗ: 5/15/30/>30 квартир, комнаты, нежилые, скрытые квартиры
(находятся зондированием), нестандартная нумерация (буквы, пропуски),
неоткрывающиеся карточки, недоступность сервиса (не считается «квартир нет»,
восстановление после краткого сбоя), похожие адреса (корпус 5к2 не
примешивается к дому 5), помещения в другом кадастровом квартале (добор).
Отдельный тест следит, что «Полные данные» не ставится ложно ни в одном
сценарии. Плюс модульные тесты сопоставления адресов, разбора карточки API,
классификации ответов (406/401/403/429/5xx/нечитаемый JSON) и полноты.
